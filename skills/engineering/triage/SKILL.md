# Triage

Move an issue, or an external pull request, through a small set of states and leave a brief an agent can execute without you in the room.

Adapted from Matt Pocock's `triage` skill (MIT, https://github.com/mattpocock/skills). State names follow that skill. Labels map onto this repo's existing `bug` / `feature` and `AFK` / `HITL` labels. This repo does not use a separate `.out-of-scope/` knowledge base or a setup wizard.

A pull request is an issue with code attached. Resolve a bare `#42` with `gh` before assuming which it is.

Every comment posted to the tracker during triage starts with:

```markdown
> *This was generated by AI during triage.*
```

## States

One category and one state. If two state labels are already present, stop and ask.

| State | Meaning | Label to apply |
|-------|---------|----------------|
| `needs-triage` | Not evaluated yet | `needs-triage` |
| `needs-info` | Blocked on the reporter | `needs-info` |
| `ready-for-agent` | Brief is complete; an agent can proceed | `AFK` |
| `ready-for-human` | Needs a human to implement or to merge | `HITL` |
| `wontfix` | Will not be done | close the item |

Category: `bug` or `feature` (an enhancement uses `feature`). Create a missing label with `gh label create` before applying it. Do not invent a second priority taxonomy; put severity in the brief.

An unlabeled item starts at `needs-triage`. `needs-info` returns to `needs-triage` after the reporter answers. Flag an unusual jump and ask before applying it.

## Invocation

The maintainer runs `/triage` and says what they want. Examples: show what needs attention, look at `#42`, move `#42` to ready-for-agent.

## Show what needs attention

List three buckets, oldest first, each line tagged `[issue]` or `[PR]`:

1. Unlabeled.
2. `needs-triage`.
3. `needs-info` where the reporter has written since the last triage note.

Show a count and a one-line summary. Let the maintainer pick. In-flight PRs from collaborators are not in these buckets unless the maintainer names one.

## Triage one item

1. **Read it.** Body, comments, labels, author, and the diff when it is a PR. Do not re-ask a question a prior triage note already resolved.
2. **Check the codebase.** Search for an existing implementation of the requested behavior, and for a duplicate issue or PR. Report where you looked.
3. **Recommend** a category and a state, with the reason, and wait.
4. **Verify the claim** before any grilling. For a bug, reproduce it from the reporter's steps (load `debugging`). For a PR, confirm the diff does what it claims and run the relevant tests. Report confirmed, failed, or insufficient detail. Insufficient detail is `needs-info`.
5. **Grill** only when the request is still underspecified. Load the model-invoked `grilling` skill. Do not start another user-invoked skill.
6. **Apply the outcome.**
   - `ready-for-agent`: post the brief below and add `AFK`.
   - `ready-for-human`: same brief, plus why it cannot be delegated, and add `HITL`.
   - `needs-info`: post the notes template. Questions are specific, not "please provide more info".
   - `wontfix`: close with a polite explanation. If it is already implemented, point at where it lives.
   - `needs-triage`: apply the label. Comment only when there is partial progress.

A quick "move #42 to ready-for-agent" skips grilling. Confirm the label change, then ask whether they want a brief.

## Agent brief

The brief is the contract. It states the outcome, not the patch. Describe behavior and acceptance criteria. Name types or interface shapes when they are the contract. Leave file paths and line numbers out — they go stale. A root-cause guess is a labelled, non-binding hypothesis.

```markdown
> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug | feature
**Summary:** one line

**Current behavior:**
**Desired behavior:**
**Repro:** steps, environment, smallest failing case (bugs)
**Constraints:**
**Out of scope:**
**Hypothesis (non-binding):** none, or a labelled guess
**Acceptance criteria:**
- [ ] observable check
**Definition of done:** the check above is green, and a PR exists that a reviewer can merge
```

## Needs-info notes

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**

- point

**What we still need from you (@reporter):**

- specific question
```

## Completion criterion

The item has one category and one state, the comment matches the template for that state, and a duplicate was linked instead of re-filed.

## Verification

- [ ] Disclaimer is the first line of the tracker comment
- [ ] Bug claims were reproduced, or the state is `needs-info`
- [ ] The brief states behavior and acceptance criteria, not a line-by-line patch
